# Тестовое задание: мини-CRM «Объекты и задачи»

> Исходный текст сохранён как получен. В источнике обрезаны пункты 2.2–2.3 (начало и таблица переходов), начало раздела 3 и конец раздела 4. Восстановленные правила описаны в `openspec/changes/mini-crm-mvp/specs/`.

Нужно сделать небольшую CRM для строительной компании. Руководитель ставит задачи по объектам (стройкам), исполнители выполняют их и отдают на проверку. Задание близко к тому, что мы делаем для клиентов каждый день.

## 1. Условия

| Параметр | Значение |
|---|---|
| Объём | 2–3 часа работы |
| Срок | как можно быстрее: если есть возможность — в тот же день. Напишите, когда приступаете и когда планируете сдать |
| Оплата | отдельно не оплачивается. Если по итогам начинаем работать вместе, время на тестовое (до 3 часов) засчитываем в рабочие часы |

Если в задании что-то непонятно или можно понять по-разному, спрашивайте. Вопросы — нормальная часть работы.

## 2. Функциональные требования

В системе две роли, объекты и задачи по объектам с циклом статусов и историей изменений.

### 2.1. Роли

| Роль | Что может |
|---|---|
| Постановщик | создаёт, редактирует и удаляет объекты и задачи; назначает исполнителя; принимает задачи или возвращает на доработку; видит всё |
| Исполнитель | видит только свои задачи и объекты, в которых у него есть задачи; берёт задачу в работу и отправляет на проверку |

Постановщиков и исполнителей может быть несколько.

### 2.4. История задачи

Каждая смена статуса сохраняется: кто, когда, из какого статуса в какой, комментарий (если есть). История видна в карточке задачи обеим ролям.

### 2.5. Экраны

- Вход по email и паролю.
- Список объектов.
- Карточка объекта со списком задач.
- Карточка задачи: данные, кнопки доступных действий, история.
- «Мои задачи» для исполнителя.

Интерфейс показывает только те действия, которые доступны текущему пользователю в текущем статусе задачи.
