# tasks Specification

## Purpose

Определяет задачи по объектам: создание, редактирование, удаление, назначение исполнителя и видимость задач для каждой роли, включая экран «Мои задачи», с защитой правил на уровне базы.

## Requirements

### Requirement: Создание задачи
Постановщик SHALL создавать задачу в объекте с названием, описанием и исполнителем. Автор и дата создания MUST устанавливаться системой, а статус новой задачи MUST быть «Новая».

#### Scenario: Создание задачи с исполнителем
- **WHEN** постановщик создаёт задачу в объекте и выбирает исполнителя
- **THEN** задача создаётся в статусе «Новая», автором указан постановщик, дата создания проставлена системой

#### Scenario: Назначать можно только исполнителя
- **WHEN** постановщик пытается назначить задачу пользователю с ролью постановщика
- **THEN** операция отклоняется

#### Scenario: Название обязательно
- **WHEN** постановщик пытается создать задачу без названия
- **THEN** создание отклоняется с ошибкой валидации

#### Scenario: Попытка задать статус, автора или дату при создании
- **WHEN** клиент, в том числе напрямую через Supabase API, передаёт при создании задачи статус, отличный от «Новая», либо чужого автора
- **THEN** запрос отклоняется или значения заменяются системными

### Requirement: Редактирование и удаление задачи
Постановщик SHALL редактировать название, описание и исполнителя задачи и удалять задачи. Исполнитель MUST NOT изменять и удалять задачи.

#### Scenario: Редактирование задачи постановщиком
- **WHEN** постановщик изменяет название или описание задачи
- **THEN** изменения сохраняются, статус задачи не меняется

#### Scenario: Исполнитель пытается изменить задачу
- **WHEN** исполнитель отправляет запрос на редактирование или удаление задачи, в том числе напрямую в Supabase API
- **THEN** запрос отклоняется или не затрагивает ни одной строки

### Requirement: Смена исполнителя
Постановщик SHALL менять исполнителя задачи, пока задача находится в статусе «Новая» или «На доработке». В других статусах смена исполнителя MUST быть отклонена на уровне базы.

#### Scenario: Смена исполнителя у новой задачи
- **WHEN** постановщик меняет исполнителя у задачи в статусе «Новая»
- **THEN** задача назначается новому исполнителю

#### Scenario: Смена исполнителя у задачи в работе
- **WHEN** постановщик пытается сменить исполнителя у задачи в статусе «В работе» или «На проверке»
- **THEN** операция отклоняется

### Requirement: Видимость задач
Постановщик SHALL видеть все задачи. Исполнитель SHALL видеть только задачи, назначенные ему. Правило MUST действовать на уровне базы.

#### Scenario: Исполнитель открывает чужую задачу
- **WHEN** исполнитель запрашивает задачу, назначенную другому исполнителю, через бэкенд или напрямую через Supabase API
- **THEN** задача не возвращается (как несуществующая)

#### Scenario: Прямой запрос списка задач
- **WHEN** исполнитель напрямую запрашивает у Supabase API все задачи
- **THEN** в ответе только задачи, назначенные ему

### Requirement: Экран «Мои задачи»
Исполнитель SHALL иметь экран «Мои задачи» со списком назначенных ему задач и их статусами.

#### Scenario: Список своих задач
- **WHEN** исполнитель открывает «Мои задачи»
- **THEN** он видит только свои задачи из всех объектов с их текущими статусами

#### Scenario: Пустой список
- **WHEN** у исполнителя нет назначенных задач
- **THEN** экран показывает пустое состояние
