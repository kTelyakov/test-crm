# Proposal

## Why

Строительной компании нужна небольшая CRM: руководитель ставит задачи по объектам (стройкам), исполнители берут их в работу и отдают на проверку. Сейчас такого инструмента нет, а это тестовое задание, которое должно показать читаемый код, архитектуру (FSD на фронтенде, DDD на бэкенде) и корректную безопасность: статусы и история задач не должны подделываться через API.

## What Changes

- Вход по email и паролю через Supabase Auth; открытой регистрации нет.
- Две роли: постановщик (`manager`) и исполнитель (`executor`), каждой может быть несколько пользователей.
- Объекты: постановщик создаёт, редактирует и удаляет; исполнитель видит только объекты, где у него есть задачи.
- Задачи по объектам: постановщик создаёт, редактирует, удаляет и назначает исполнителя; исполнитель видит только свои задачи.
- Цикл статусов задачи со строгой таблицей переходов и проверкой роли на сервере.
- Неизменяемая история смен статуса (кто, когда, из какого статуса в какой, комментарий), видна обеим ролям.
- Экраны: вход, список объектов, карточка объекта со списком задач, карточка задачи (данные, доступные действия, история), «Мои задачи».
- Отдельный бэкенд на TypeScript (DDD) между фронтендом и Supabase; RLS в БД как вторая линия защиты.
- Миграции БД, сид (1 постановщик, 2 исполнителя, 2–3 объекта, задачи в разных статусах), README, деплой.

## Capabilities

### New Capabilities
- `auth`: вход по email и паролю, роли пользователей, запрет открытой регистрации, защита API.
- `sites`: управление объектами и видимость объектов по ролям.
- `tasks`: создание, редактирование, удаление и назначение задач, видимость задач по ролям, экран «Мои задачи».
- `task-workflow`: статусы задачи, допустимые переходы, обязательный комментарий, история смен статуса, набор доступных действий.

### Modified Capabilities

Нет: проект новый, существующих спеков нет.

## Impact

- Новые каталоги: `frontend/` (React, FSD), `backend/` (Node/TypeScript, DDD), `supabase/` (миграции, сид).
- Внешние системы: Supabase (Postgres, Auth), хостинг фронтенда и бэкенда.
- Секреты: `service_role` только в переменных окружения бэкенда и в локальном сид-скрипте, не в репозитории и не во фронтенде.
