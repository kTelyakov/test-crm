# Proposal

## Why

Строительной компании нужна небольшая CRM: руководитель ставит задачи по объектам (стройкам), исполнители берут их в работу и отдают на проверку. Это тестовое задание (полный текст в `docs/TZ.md`), где оцениваются логика, защита данных и понимание сделанного. Ключевое требование: права и переходы статусов защищены на уровне базы и работают даже при обращении к Supabase напрямую, в обход интерфейса.

## What Changes

- Вход по email и паролю через Supabase Auth; открытой регистрации нет.
- Две роли: постановщик (`manager`) и исполнитель (`executor`), каждой может быть несколько пользователей.
- Объекты (название, адрес): постановщик создаёт, редактирует и удаляет; исполнитель видит только объекты, где у него есть задачи.
- Задачи (название, описание, объект, исполнитель, статус, автор, дата создания): постановщик создаёт, редактирует, удаляет и назначает исполнителя; исполнитель видит только свои задачи.
- Правила переходов статусов хранятся как данные в таблице БД и исполняются функцией в БД; запрещённый переход не проходит ни через интерфейс, ни через прямой запрос.
- Права доступа заданы политиками RLS; статус и историю нельзя изменить, обойдя функцию перехода.
- Неизменяемая история смен статуса (кто, когда, из какого статуса в какой, комментарий), видна обеим ролям.
- Экраны: вход, список объектов, карточка объекта со списком задач, карточка задачи (данные, доступные действия, история), «Мои задачи».
- Тонкий бэкенд на TypeScript (DDD) между фронтендом и Supabase: работает под токеном пользователя, читает те же правила из БД, отдаёт типизированный OpenAPI-контракт.
- Сдача: миграции БД, сид (1 постановщик, 2 исполнителя, 2–3 объекта, задачи в разных статусах), README, объяснение для руководителя-непрограммиста, список решений и допущений, деплой.

## Capabilities

### New Capabilities
- `auth`: вход по email и паролю, роли пользователей, запрет открытой регистрации, защита API и секретов.
- `sites`: управление объектами, видимость объектов по ролям, защита на уровне БД.
- `tasks`: создание, редактирование, удаление и назначение задач, видимость по ролям, экран «Мои задачи».
- `task-workflow`: статусы, правила переходов как данные, проверка в БД, история смен статуса, набор доступных действий.

### Modified Capabilities

Нет: проект новый, существующих спеков нет.

## Impact

- Новые каталоги: `frontend/` (React, FSD), `backend/` (Node/TypeScript, DDD), `supabase/` (миграции, сид), `e2e/` (Playwright), `docs/`.
- Внешние системы: Supabase (Postgres, Auth), хостинг фронтенда и бэкенда.
- Секреты: `service_role` не используется приложением; он нужен только локальному сид-скрипту и не попадает в репозиторий и во фронтенд.
