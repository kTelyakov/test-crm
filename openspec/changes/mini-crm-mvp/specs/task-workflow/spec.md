# Spec Delta

## Purpose

Определяет жизненный цикл задачи: статусы, разрешённые переходы с проверкой роли, обязательные комментарии, неизменяемую историю смен статуса и набор действий, доступных пользователю.

## ADDED Requirements

### Requirement: Статусы задачи
Задача SHALL находиться ровно в одном из статусов: «Новая», «В работе», «На проверке», «Принята», «На доработке».

#### Scenario: Начальный статус
- **WHEN** задача создана
- **THEN** её статус «Новая»

### Requirement: Разрешённые переходы
Система SHALL разрешать только следующие переходы: «Новая» → «В работе» (назначенный исполнитель); «В работе» → «На проверке» (назначенный исполнитель); «На проверке» → «Принята» (постановщик); «На проверке» → «На доработке» (постановщик); «На доработке» → «В работе» (назначенный исполнитель). Любой другой переход MUST быть отклонён.

#### Scenario: Исполнитель берёт задачу в работу
- **WHEN** назначенный исполнитель берёт задачу в статусе «Новая» в работу
- **THEN** статус становится «В работе»

#### Scenario: Исполнитель отправляет задачу на проверку
- **WHEN** назначенный исполнитель отправляет задачу в статусе «В работе» на проверку
- **THEN** статус становится «На проверке»

#### Scenario: Постановщик принимает задачу
- **WHEN** постановщик принимает задачу в статусе «На проверке»
- **THEN** статус становится «Принята»

#### Scenario: Постановщик возвращает задачу на доработку
- **WHEN** постановщик возвращает задачу в статусе «На проверке» на доработку с комментарием
- **THEN** статус становится «На доработке»

#### Scenario: Исполнитель возобновляет работу
- **WHEN** назначенный исполнитель берёт в работу задачу в статусе «На доработке»
- **THEN** статус становится «В работе»

#### Scenario: Недопустимый переход
- **WHEN** запрашивается переход, которого нет в таблице (например, «Новая» → «Принята»)
- **THEN** запрос отклоняется, статус и история не меняются

#### Scenario: Переход выполняет не тот пользователь
- **WHEN** исполнитель, которому задача не назначена, или постановщик пытается выполнить переход исполнителя (либо исполнитель — переход постановщика)
- **THEN** запрос отклоняется, статус и история не меняются

#### Scenario: Принятая задача завершена
- **WHEN** задача находится в статусе «Принята»
- **THEN** никакие переходы из неё недоступны

### Requirement: Обязательный комментарий при возврате
При возврате задачи на доработку комментарий MUST быть обязательным. Для остальных переходов комментарий SHALL быть необязательным.

#### Scenario: Возврат без комментария
- **WHEN** постановщик возвращает задачу на доработку с пустым комментарием
- **THEN** запрос отклоняется с ошибкой валидации, статус не меняется

#### Scenario: Переход без комментария
- **WHEN** исполнитель берёт задачу в работу без комментария
- **THEN** переход выполняется, в истории комментарий пуст

### Requirement: Неизменяемая история статусов
Каждая смена статуса SHALL сохраняться в истории с автором, временем, прежним и новым статусом и комментарием (если есть). Запись истории и смена статуса MUST выполняться атомарно. Записи истории MUST NOT создаваться, изменяться или удаляться напрямую через API.

#### Scenario: Запись при смене статуса
- **WHEN** выполняется допустимый переход
- **THEN** создаётся запись с автором, временем, статусами «из» и «в» и комментарием

#### Scenario: Атомарность
- **WHEN** сохранение записи истории не удалось
- **THEN** статус задачи остаётся прежним

#### Scenario: Попытка подделать историю
- **WHEN** клиент пытается напрямую создать, изменить или удалить запись истории или изменить статус задачи в обход перехода
- **THEN** операция отклоняется

### Requirement: Просмотр истории
История задачи SHALL отображаться в карточке задачи обеим ролям в хронологическом порядке.

#### Scenario: Постановщик и исполнитель видят историю
- **WHEN** постановщик или назначенный исполнитель открывает карточку задачи
- **THEN** он видит все записи истории этой задачи

### Requirement: Доступные действия в интерфейсе
Интерфейс SHALL показывать только те действия, которые доступны текущему пользователю при текущем статусе задачи. Проверка на сервере MUST выполняться независимо от интерфейса.

#### Scenario: Исполнитель видит кнопку только своего перехода
- **WHEN** назначенный исполнитель открывает задачу в статусе «Новая»
- **THEN** он видит только действие «Взять в работу»

#### Scenario: Постановщик на проверке
- **WHEN** постановщик открывает задачу в статусе «На проверке»
- **THEN** он видит действия «Принять» и «Вернуть на доработку»

#### Scenario: Нет доступных действий
- **WHEN** пользователь открывает задачу, по которой у него нет допустимых переходов
- **THEN** кнопки смены статуса не отображаются
