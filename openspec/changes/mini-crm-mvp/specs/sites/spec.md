# Spec Delta

## Purpose

Определяет объекты (стройки): их создание и изменение постановщиками, видимость объектов для каждой роли и защиту этих правил на уровне базы.

## ADDED Requirements

### Requirement: Управление объектами
Постановщик SHALL создавать, редактировать и удалять объекты. Объект содержит название и адрес; оба поля обязательны.

#### Scenario: Создание объекта
- **WHEN** постановщик отправляет форму нового объекта с названием и адресом
- **THEN** объект создаётся и появляется в списке объектов

#### Scenario: Обязательные поля
- **WHEN** постановщик пытается сохранить объект без названия или без адреса
- **THEN** сохранение отклоняется с сообщением об ошибке валидации

#### Scenario: Исполнитель не управляет объектами
- **WHEN** исполнитель пытается создать, изменить или удалить объект через интерфейс или API
- **THEN** операция отклоняется, а интерфейс не показывает соответствующие элементы управления

### Requirement: Удаление объекта с задачами
Система MUST NOT удалять объект, у которого есть задачи.

#### Scenario: Удаление объекта с задачами
- **WHEN** постановщик удаляет объект, содержащий хотя бы одну задачу
- **THEN** операция отклоняется с объяснением, что сначала нужно удалить задачи

#### Scenario: Удаление пустого объекта
- **WHEN** постановщик удаляет объект без задач
- **THEN** объект удаляется

### Requirement: Видимость объектов
Постановщик SHALL видеть все объекты. Исполнитель SHALL видеть только объекты, в которых ему назначена хотя бы одна задача.

#### Scenario: Список объектов исполнителя
- **WHEN** исполнитель открывает список объектов
- **THEN** он видит только объекты, где ему назначена задача

#### Scenario: Прямой доступ к чужому объекту
- **WHEN** исполнитель запрашивает объект, в котором у него нет задач
- **THEN** объект не возвращается (как несуществующий)

### Requirement: Защита объектов в обход интерфейса
Правила доступа к объектам MUST действовать на уровне базы данных, в том числе при прямых запросах к Supabase API с токеном пользователя.

#### Scenario: Прямое чтение чужих объектов
- **WHEN** исполнитель напрямую запрашивает список объектов у Supabase API
- **THEN** в ответе только объекты, где ему назначены задачи

#### Scenario: Прямая запись объектов исполнителем
- **WHEN** исполнитель напрямую отправляет в Supabase API запрос на создание, изменение или удаление объекта
- **THEN** запрос отклоняется или не затрагивает ни одной строки, данные не меняются

### Requirement: Карточка объекта
Карточка объекта SHALL показывать данные объекта и список его задач со статусами, отфильтрованный по правам пользователя.

#### Scenario: Карточка для постановщика
- **WHEN** постановщик открывает карточку объекта
- **THEN** он видит все задачи объекта

#### Scenario: Карточка для исполнителя
- **WHEN** исполнитель открывает карточку объекта
- **THEN** он видит только свои задачи этого объекта
